# 架构评估与建议

更新：2026-10-16。依据：七份功能现状文档（[编辑](EDIT_CURRENT_STATE.md)、[编码](ENCODING_CURRENT_STATE.md)、[十六进制](HEX_CURRENT_STATE.md)、[大文件](LARGE_FILE_CURRENT_STATE.md)、[保存恢复](SAVE_RECOVERY_CURRENT_STATE.md)、[加密锁定](SECURITY_CURRENT_STATE.md)、[账号库](ACCOUNTS_CURRENT_STATE.md)）、[搜索现状](SEARCH_CURRENT_STATE.md)、[源码架构](DESIGN.md) 和源码。目标约束见 [产品目标](PRODUCT_GOALS.md)：原生 Qt Widgets、轻快、今后加功能只补模块、局部故障不拖垮整体。

## 1. 结论

现在的架构**底层扎实、中心臃肿、扩展点是空壳**。

- 底层的文件读取、编码、PCRE2 搜索、原子保存、会话恢复、KDBX 后端、异步任务，边界清楚、测试多，可以保留。
- 用户能感到的问题几乎都出在两个中心对象：`EditorTab`（约 8,000 行，分在 9 个文件里，头文件 21 个 `is/has/can/supports` 状态判断）同时是文本编辑器、十六进制编辑器、只读大文件视图的宿主、Scintilla 桥、搜索适配器、保存快照和会话端口；`MainWindow`（约 5,900 行）同时管菜单、命令、打开路由、保存与关闭流程、登录框、锁定编排、自动保存计时、系统锁屏、账号与安全中心页面。
- “插件化”的部分大多没有第二个实现：文档 Provider 注册表最后都回到同一个 `EditorTab::openSurface()`；文档工具、推理注册表为空；功能注册表只是命令 ID 白名单。它们增加了理解成本，却没有带来可替换性或隔离。
- 行数预算让文件按大小拆，而不是按职责拆：`EditorTabHex.cpp`、`EditorTabSearch.cpp` 是同一个类的分片，不是模块。

模块化方向本身是对的，问题是**切错了轴**：现在按技术层切（domain / runtime / app），而功能仍然汇聚在两个大类里；应该按“一种文档视图”“一个功能”切。

## 2. 现状问题如何追到架构

| 现状文档里的问题 | 架构原因 |
|---|---|
| 排序、书签只作用于主编辑器，分屏时用错一侧；书签命令在十六进制下可点 | 一个类里多种表面共存，各命令自己挑 `m_editor` 还是 `activeTextEditor()` |
| 缩放只作用于主编辑器、只读视图上的“兼容表面” | 同上；源码注释写明 `editor()` 是“兼容表面” |
| 保存上限按 UTF-8 工作文本计、文案写“工具快照” | 保存复用了为文档工具设计的快照接口 |
| 原型设计改一处要核对七份文档 | 规则散落在 `MainWindow` 的流程函数和对话框里，没有一个不依赖界面的“文档工作区”可以直接复用 |
| 锁定、关闭、保存的流程很难换成新界面 | 流程与 `QMessageBox`、菜单状态写在一起 |

## 3. 关于“故障隔离”

单个静态 exe 里，任何模块崩溃都会带走整个进程；模块和插件在同一进程里**不能隔离崩溃**。对这个产品真正有用、而且现在已经部分做到的隔离是四层：

1. **数据不丢**：原子保存、恢复稿、加密恢复点、无效清单保全。崩了重启能找回（核心旅程 J6）。这是最重要的一层，已经扎实。
2. **单个文档失败不影响其他文档**：恢复失败的标签变成“待处理”页面，其他标签照常。这个模式应推广到打开、保存、搜索。
3. **操作失败返回结果，不抛到界面**：`VaultError`、`PersistenceResult` 已经这样做；模块出错时禁用自己的命令并显示原因，而不是弹一串对话框。
4. **真正不可信或高风险的扩展放到独立进程**：以后的 AI、代码解析、外部工具，用子进程加类型化消息通信，崩了只影响该功能。这才是“插件”该用的地方。

所以建议：**进程内用编译期模块，不做动态插件；只有高风险扩展走进程外。**

## 4. 建议的结构

```
Shell（新界面）
  标题栏标签、命令面板、状态栏、浮层、主题令牌、设置页框架
  只认命令、视图接口和模块注册，不含业务流程
        │
功能模块（编译期注册，互不依赖）
  搜索      查找浮层、结果面板          → 用搜索引擎和视图接口
  账号      账号工作区                  → 用 VaultService
  安全      登录、锁定、安全设置分区    → 用安全会话服务
  恢复      待处理页面、保全确认
        │
文档视图（同一个接口，三个实现）
  TextEditView      QScintilla，普通与加密文本
  HexEditView       VirtualFileView + PatchList，可编辑二进制
  ReadOnlyView      WindowedReadOnlyProvider，大文件文本/十六进制、跟随
        │
文档核心（不依赖界面）
  DocumentWorkspace 打开、保存、关闭、锁定、恢复的编排；需要用户决定时通过“提问端口”
  持久化（普通 / 加密）、会话与恢复稿、编码、搜索引擎、文件读取、异步任务、KDBX 后端
```

要点：

1. **一个视图接口取代模式判断**：`IDocumentView` 声明自己的能力（可编辑、可分屏、有语法、字节寻址……），提供选区、光标、复制、高亮、导航。命令只问“当前视图能不能做”。切换文本/十六进制就是换一个视图对象。排序、书签、缩放这类问题会自然消失。
2. **DocumentWorkspace 把流程从 MainWindow 拿出来**：保存冲突、关闭询问、锁定顺序、自动保存、系统锁屏、无效清单保全，都写成不依赖界面的服务，需要用户决定时调用一个“提问端口”（新界面用浮层或对话框实现，测试用假实现）。新界面因此可以换掉所有对话框而不碰规则。
3. **功能模块按竖切**：每个模块向 Shell 注册命令（ID、名称、快捷键、可用条件）、可选的面板或工作区、设置分区。`CommandRegistry` 集中判断可用性的思路保留，但条件由模块和视图提供，不再由 MainWindow 拼一个大上下文。
4. **依赖规则替代行数预算**：模块只依赖核心和 Shell 接口，彼此不依赖；视图不依赖模块。`check_architecture.ps1` 改为检查这些依赖方向。
5. **删掉没有第二个实现的抽象**：空的工具 / 推理注册表、功能白名单、路由回同一对象的 Provider 层、遗留的 `setEncodingFromAction`。等真正有第二个实现时再加。
6. **以后加功能**：同进程、可信的功能（例如代码折叠增强、diff）写成新模块；不可信或重的（AI、解析器）做成子进程服务加一个薄模块。

## 5. 迁移顺序

新界面本来就要重做外壳，顺势按下面的顺序走，每步都用 [核心旅程](PRODUCT_GOALS.md) J1–J12 和现有核心测试守住，不做一次性重写：

1. **主题令牌与新外壳**：标题栏标签、状态栏、命令面板、浮层框架，接现有 `CommandRegistry` 和现有对话框。只换外观，不动规则。
   *2026-10-17 已实现（分支 `feat/simplify-and-shell`）*：令牌、无边框窗口与标题栏、≡ 主菜单（菜单栏隐藏）、绘制的文档标签、可点击状态栏、Ctrl+K 命令面板、提示条。新代码在 `src/shell/`，`MainWindow` 只做接线。标签暂时仍在标题栏下方单独一行；查找浮层、设置页、命令面板里的账号项各自留给后续计划。
2. **抽出 DocumentWorkspace**：把保存、关闭、锁定、自动保存、恢复流程从 `MainWindow` 移出，接“提问端口”。`MainWindow` 只剩外壳。
3. **拆 `EditorTab` 为三个视图**：先定义 `IDocumentView`，再逐个迁出文本、十六进制、只读视图；同时修掉排序、书签、缩放、保存上限的问题。
4. **搜索模块**：查找浮层替换独立对话框，结果面板换新样式；搜索引擎和语义（见搜索现状）不变。（2026-10-18 已完成）
5. **账号与安全模块**：新账号工作区、登录与锁定界面、设置页安全分区，建在现有 VaultService 和安全会话服务上。
6. **清理**：删除空注册表和遗留代码，依赖检查替换行数预算。

第 1、4、5 步主要是界面工作，可以和第 2、3 步交错；第 3 步风险最高，应在第 2 步完成后进行。

## 6. 不建议做的

- 动态加载 DLL 插件：签名、ABI、安全审查成本高，对一个装秘密的程序是新的攻击面，也不能隔离崩溃。
- 一次性重写编辑器或换编辑内核：QScintilla、PCRE2 和窗口化只读视图是现在最可靠的部分。
- 继续加治理文档和预算：用核心旅程和依赖规则代替。

## 7. 现有架构检查

构建时自动运行，失败即构建失败：

| 入口 | 保护内容 | 不能证明 |
|---|---|---|
| `tools/check_architecture.ps1` | CMake 不重复编译源文件；领域层不依赖界面或 KeePass；外壳 `src/shell` 不包含编辑器、窗口或保险库头文件；装配、持久化与搜索的所有权；`MainWindow`、`EditorTab` 等的行数、分支和方法数预算 | 完整依赖图、状态一致性或客户端正确性 |
| `tools/check_async_threading.ps1` | 线程与线程池只在允许的运行时边界创建 | 取消、映射释放、重入或退出安全 |
| `tests/test_architecture_contracts.cpp` | 命令、注册表与组件接口的合同，包括已删除命令不再注册 | 真实界面行为 |

预算是防回退信号，不是复杂度证明：`MainWindow` 已贴近方法数和分支数上限，新功能应进入 `src/shell` 或独立模块，由 `MainWindow` 只做接线；不通过提高阈值腾出空间。
