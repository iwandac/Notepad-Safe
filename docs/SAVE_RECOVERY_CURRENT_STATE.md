# 保存与恢复现状

更新：2026-10-16。按当前源码记录保存、另存为、外部修改冲突、关闭提示、自动保存与会话恢复。加密文档的加解密细节见加密与锁定现状。来源：[`MainWindowDocuments.cpp`](../src/window/MainWindowDocuments.cpp) 的 `saveFile`/`saveAsFile`/`resolveExternalSaveConflict`、[`MainWindowCommands.cpp`](../src/window/MainWindowCommands.cpp) 的 `maybeSaveTab`、[`MainWindowSession.cpp`](../src/window/MainWindowSession.cpp) 的 `closeEvent`、[`MainWindow.cpp`](../src/window/MainWindow.cpp) 的计时器、[`PlainFilePersistence.cpp`](../src/app/PlainFilePersistence.cpp)、[`SaveAsDialog.cpp`](../src/app/SaveAsDialog.cpp)、[`SessionManager.cpp`](../src/session/SessionManager.cpp)、[`SessionDocumentPort.h`](../src/domain/SessionDocumentPort.h)、[`WorkspaceRecoveryCoordinator.cpp`](../src/window/WorkspaceRecoveryCoordinator.cpp)、[`RecoveryIssuePage.cpp`](../src/window/RecoveryIssuePage.cpp)；保存与恢复的验证记录见 [执行账本](DAILY_USE_CLOSEOUT.md)。

## 1. 新建

- 文件 › 新建（Ctrl+N）在 KDBX 后端可用时新建**加密草稿**（菜单文字“新建（默认安全保存）”）；构建不含 KDBX 时新建普通未命名文档。
- 加密草稿一建立就在数据目录 `drafts/<ID>.nsafe-draft` 有自己的加密文件；保存（含自动写回）静默写到这里，**不弹位置对话框**。标签标题取正文前 8 行中第一行非空文字（去掉开头的 `#`，最多 80 字），否则为“未命名”。只有“另存为”才选位置、生成可携带的 `.nsafe` 文件或转为普通文件。

## 2. 保存（Ctrl+S）

普通文件依次经过：

1. 只读大文件不能保存（“当前文档为只读分析模式，不能保存或另存。”）。
2. 未命名的普通文档 → 转为另存为（加密草稿不走这里，见第 1 节）。
3. 打开时有非法字节的文本 → “编码需要确认”（见编码现状）。
4. **外部修改检查**：若磁盘文件在打开后变了，弹“文件已在磁盘上更改 / 为避免覆盖其他程序的修改，本次保存已暂停。”
   - 变化：按钮“重新加载磁盘版本”“另存为…”“取消”（默认取消）。
   - 被移动或删除、或无法读取确认：只有“另存为…”“取消”。
   - **没有“仍然覆盖”选项。**
5. 快照：把正文转成 UTF-8 快照，超过 32 MiB 失败（见编码现状的已知问题）。
6. 编码：按文档编码写，旧式编码遇到不能表示的字符失败；写回 BOM。
7. **原子写入**：`QSaveFile` 写临时候选，写完并释放底层句柄后再核对一次磁盘版本，一致才替换原文件。任一步失败提示“无法保存文件…原文件未更改”，修改保留。
8. 成功后清除该文档的恢复稿。

外部修改检测靠身份、大小、修改时间和有界采样哈希，不是全文比对；最后核对与替换之间仍有极小竞争窗口（详见执行账本）。可编辑文档**没有文件监视**，外部修改只在保存时发现，不会在编辑期间主动提示。

## 3. 另存为（Ctrl+Shift+S）

- 自有对话框：文件名、位置、保存类型（“未加密文件 (*)”或“Notepad Safe 安全文档 (*.nsafe)”）。默认类型跟随当前文档：加密文档默认安全类型。
- 普通 → 安全：内容须小于 32 MiB，否则提示“安全文档只接受小于 32 MiB 的内容”；需要可用的安全会话；自动补 `.nsafe`。
- 安全 → 普通：写出明文文件，不产生明文备份。
- 普通保存永远保持当前类型；类型转换只发生在另存为。

## 4. 关闭

**关闭单个标签**（Ctrl+W、标签 ×、右键“关闭/关闭其他/关闭全部”）：

- 加密文档有修改：直接写回 KDBX（失败则阻止关闭），不弹“是否保存”。
- 未修改：直接关；空的未命名文档顺带清掉恢复稿。
- 其余有修改的：弹“标签 "X" 已修改。是否保存更改？”保存 / 不保存 / 取消；未命名选择保存时走另存为，另存为取消视为取消关闭；不保存会删除该文档的恢复稿。

**关闭窗口**（仿 Notepad++）：

1. 暂停自动保存与会话到期计时。
2. 逐个标签：加密文档写回 KDBX；**未命名且有内容不提示**，留给会话恢复；**已有文件的修改若已有恢复稿也不提示**；只有“已有文件 + 有修改 + 没有恢复稿”才弹保存 / 不保存 / 取消。任何一个取消就中止关闭并恢复计时器。
3. 立即提交一次会话（`saveSessionNow`）。失败则中止关闭，账号库和文档区保持可用以便重试。
4. 上次会话清单损坏、不可读或版本不支持时，这一步会先问“保全旧资料并保存当前会话 / 取消”（默认取消），见第 7 节。

## 5. 自动保存

| 对象 | 时机 | 写到哪里 |
|---|---|---|
| 普通文档的未保存修改、未命名文档 | 每 30 秒，若有未保存内容就提交一次会话 | 恢复稿 `.ndraft`，用 Windows DPAPI 按当前用户加密 |
| 加密文档 | 从“未修改”变为“已修改”后 5 秒写回自己的 KDBX 文件，同时按正文刷新标题（安全会话忙时 1 秒后重试；失败 30 秒后再试） | 原 `.nsafe` 文件；只在安全会话已解锁时进行，锁定时不弹解锁框 |
| 加密文档写回失败时 | 同上 | 本机加密恢复点；状态栏提示“自动保存失败；最新内容已加密恢复，将在稍后重试。”两者都失败时提示“请立即手动保存” |
| 二进制文档 | 随会话 | 加密的字节补丁日志 |

普通文档**不会自动写回原文件**，只写恢复稿；加密文档会自动写回原文件。

## 6. 会话内容与启动恢复

会话清单 `session.json` 位于数据目录（`NOTEPADSAFE_DATADIR`，否则系统数据目录下的 NotepadSafe），每个标签记录：路径、编码、语言、光标行列或字节位置、选区、是否修改、恢复稿路径、是否加密文档及其 ID、呈现方式（文本/十六进制）、十六进制插入模式、分屏及方向。

- 提交顺序：先逐个写恢复稿，全部成功后才原子提交清单；任一必需恢复稿失败就不发布新清单、不清理旧恢复稿。各恢复稿是逐个写的，不是跨文件事务（详见执行账本）。
- 启动时在首屏绘制后恢复：恢复所有标签与顺序、活动标签、位置；有未保存修改的标签以原名显示为已修改。状态栏提示“已恢复 N 个标签页”或“已恢复 N 个标签页（含未保存修改）”，3 或 5 秒后消失；**没有横幅或对话框**。
- 加密恢复稿需要原 Windows 用户环境；加密文档恢复需要安全会话。恢复上次未写入 KDBX 的加密内容时提示“已恢复上次未写入 KDBX 的本机加密内容，请确认后保存。”
- **恢复失败的标签**变成“待处理”页面：标题“未能重新打开 X”或“未能恢复 X 的未保存修改”，说明原因（原文件不存在、恢复稿缺失或损坏、无法解锁、原文件已变化、路径已变成安全文件等）、技术详情、“重试打开/重试恢复”、“移除标签/放弃恢复”（放弃需二次确认，会删除受管恢复稿，不动原文件）。状态栏提示“已恢复 N 个标签页，M 项尚未完成…”且不自动消失。
- 未被清单引用、超过 7 天的旧恢复稿在启动时清理；清单无效时不清理。

## 7. 无效会话清单的保全

清单损坏、不可读、版本或结构不支持时：

- 启动时不自动覆盖或清理，状态栏提示。
- 自动保存、锁定、会话到期不处理它。
- 只在明确关闭窗口时询问“保全旧资料并保存当前会话 / 取消”。选择保全：把旧清单和本应用范围内的旧恢复稿复制到 `recovery-preserved/<UUID>/`，逐个比对长度与 SHA-256，全部成功才写索引；当前正文写到新恢复稿路径，全部成功后才提交新清单，然后允许退出。任何一步失败都不退出，原资料保持不动，可重试。完成后提示“当前会话已保存。旧会话资料保全于：…”。

## 8. 其他

- 文件 › 从磁盘重新加载：放弃当前修改并重读（有修改时先确认“重新加载将丢弃 X 的未保存修改”）。
- 最近打开：最多 10 个，打开不存在的文件时从列表移除并提示；可清除列表。
- 已打开同一物理文件时再次打开会切到已有标签。

## 9. 新界面原型与现状的差异

| # | 差异 | 现状 | 处理 |
|---:|---|---|---|
| 1 | 启动恢复横幅（状态画板） | 只有状态栏提示，几秒后消失 | 横幅是新设计；需决定是否替换状态栏提示 |
| 2 | 保存失败横幅“重试 / 另存为” | 现状是模态错误框，修改保留 | 横幅属于交互改动，规则不变 |
| 3 | 外部修改对话框“覆盖磁盘版本” | **现状没有覆盖选项**，只有重新加载 / 另存为 / 取消 | 原型多画了覆盖按钮，需删除或另行决定 |
| 4 | 关闭时“一次列出全部未保存文档” | 现状逐个标签弹窗；未命名和已有恢复稿的不弹 | 合并列表属于新交互；仍需保留“未命名不提示、交给会话恢复”的规则 |
| 5 | 加密文档“未保存”状态 | 加密文档 5 秒后自动写回 KDBX | 原型状态栏“已保存/未保存”需体现“正在写回 / 已写回 / 写回失败已加密恢复” |
| 6 | 加密文档扩展名 | `.nsafe`（KDBX 格式） | 原型写成 `.kdbx`，需改为 `.nsafe` |
| 7 | 编辑期间的外部修改提示 | 没有，保存时才发现 | 如需主动提示属于新功能 |
| 8 | 待处理恢复页面 | 现状有完整页面 | 原型未画，待设计 |
