## 1. 当前成熟度结论

Notepad Safe 已经是功能广、架构基础较强的高级开发预览，不是功能原型；但性能、故障恢复与真实 AI 能力仍需验收。历史 KDBX=ON 153/153 与 KDBX=OFF 140/140 只证明相应构建中的已登记行为，不能替代当前源码、真实故障和视觉证据。

**2026-08-30 产品范围裁决：不做 Windows 发布、安装、打包分发、签名、商店、安装升级/回滚/卸载或发布渠道工作。本轮性能成熟度完成后直接进入 AI 设计收敛。** 原第4轮保留为历史设计，不执行、不视为通过，也不再是任何 AI 阶段的前置。Windows 原生运行、Release 优化构建、KDBX ON/OFF、数据兼容与安全测试仍然保留；它们不是安装发布工作。

## 2. 产品目标与固定边界

产品目标保持不变：文件离线时默认安全，解锁使用时就是普通记事本；普通文本、二进制、安全文档、账户库、大文件浏览、搜索、恢复和后续文档工具共享一套清晰的用户旅程。

固定边界：

- `<32 MiB` 文本/小型二进制可编辑；`>=32 MiB` 只读浏览和分析；2 GiB 只保留分级意义。
- 保存保持当前文件类型；格式转换只经“另存为”；失败不破坏原文件。
- 账号密码、TOTP seed、恢复材料和密钥永不进入通用文档工具、AI 或代码分析。
- AI/代码图默认只读取用户明确选择的范围；结果先预览，修改必须经差异确认和一次 Undo，绝不自动保存或执行。
- 代码/脚本可视化是静态解释，不导入模块、不安装依赖、不启动 Shell、不运行脚本。
- 核心编辑、打开、保存、搜索和恢复不依赖网络。

## 3. 成熟度路线

每轮是一个可端到端验收的垂直切片；未通过的质量门不得用新功能掩盖。保留原轮次编号以追溯已完成证据，但执行顺序按依赖，不再机械地按编号串行。

| 轮次 | 目标 | 设计与开发范围 | 退出证据 |
|---:|---|---|---|
| 0 | 发布真值与统一门禁 | 收敛冲突文档；建立单一 `release_gate` 编排与 manifest；把历史证据和本轮证据分栏 | 干净隔离构建可枚举 ON/OFF、架构、供应链、GUI、E2E、ASAN、性能、包验证步骤；任何缺项显式失败 |
| 1 | Hex 数据完整性闭环 | B1 边缘滚动/跨窗口选择；B2/B3 入口与只读边界；Find Next/Prev；保存冲突/失败；各编辑原语恢复 | 结构化字节夹具逐字节 hash；正式 EXE 强杀恢复；100%–200% DPI、主题、键盘与读屏；原文件无误写 |
| 2 | 核心旅程与产品语言 | 单实例外部打开；搜索真值复核；大日志 Tail；只读原因与安全术语改为用户语言 | 双进程/同文件/session 竞争测试；搜索混合矩阵；Tail 追加/截断；无工程术语泄漏的视觉复核 |
| 3 | 性能与故障恢复 | 30 轮 P50/P95、RSS/句柄/线程/UI heartbeat；256 MiB、近 2 GiB、4 GiB+；Plain/Secure/Accounts 故障注入 | 峰值内存不随文件大小线性增长；取消与首屏达标；每个失败点至少保留一个可验证版本且无明文残留 |
| 4 | Windows 分发（排除） | 原设计仅留档；不开发、不验收、不申请证书或发布权限 | 不适用，不作为 AI 前置，不标为已完成 |
| AI-D0 | AI 设计收敛 | 复用既有AI总体与第5–8轮设计，明确首个用户旅程、范围权限、模型/运行方式、语言与验收数据 | 一份获批的实现清单与子代理任务合同；未决能力保持禁用，不重建重复设计体系 |
| 5 | 安全文档工具基座 | `ApprovedDocumentSlice`、typed artifact/annotation/edit、一次性授权、预览/Diff/单次 Undo；确定性生产 Tool 打通 UI | 默认选区；无选区需明确全文动作；stale/cancel/lock/close 全部 fail closed；Accounts denied；首帧零重型实例 |
| 6 | 代码与脚本可视化 | 固定供应链 parser → `CodeModel` → 产品语言步骤/数据流图；节点点击回源码；不执行脚本 | 首批语言 golden；每条结论绑定源码范围和置信级；畸形输入/深度/节点/时间/内存有界；图中无外链或脚本 |
| 7 | 本地 AI 文本助手 | 本地 Provider 策略、健康检查、流式输出、超时/取消；解释、总结、改写、续写、按要求生成；结果预览与差异应用 | 真实本地模型 E2E；输入/输出预算、首 token、取消延迟；无自动下载/远程 fallback/日志正文；一次 Undo 恢复 |
| 8 | 可选远程 AI | 仅在产品明确批准后实现 HTTPS Provider、密钥安全存储、逐次范围确认、费用/保留提示 | 每次授权绑定文档/revision/range/provider/有效期；本地失败不转远程；供应商策略与网络失败均 fail closed |
| 9 | AI 组合产品验收 | 核心记事本与AI共同运行，清除测试替身入口与重复状态，复核数据/隐私/性能/视觉 | 同一源码与EXE身份的真实用户旅程；零P0/P1；不要求签名包、安装或公开发布 |

执行主线：**第3轮 → AI-D0 → 第5轮共用基座 → 第7轮文本助手优先；第6轮代码可视化在基座后独立推进 → 第8轮选定策略 → 第9轮组合验收。** 第6轮全部语言完成不是文本助手的前置；只有使用代码结构事实增强AI解释时，才依赖相应语言的CodeModel。资源足够且文件责任不冲突时可委派两个独立子代理开发文本与代码切片，根代理统一设计、验收和打回。

第8轮默认维持远程禁用；其拒绝策略可在AI-D0确认并随第5/7轮补证，不阻塞本地文本助手。用户不批准远程供应商时不等待联网接入，也不以测试替身冒充远程能力。

## 4. 每轮固定设计—开发—验收循环

1. **设计**：写用户任务、数据边界、失败方式、可见结果和停止条件；先列受影响的 FeatureId。
2. **红灯**：先增加能在旧实现上失败的行为测试、negative double 或故障注入。
3. **开发**：子代理实现一个垂直切片；不得扩展范围或修改产品决策。
4. **验收**：主代理检查 diff、源码责任、数据结果、正式 Release 动态 GUI 和视觉证据。
5. **打回**：任何数据误写、秘密泄露、旧功能回退、伪测试、性能越界或文档漂移都回到同一轮返工。
6. **收敛**：只有全部门禁通过才更新本路线、功能总账和证据 manifest；不以“代码已写”标完成。

测试必须与改动成比例：开发期运行最小定向门；阶段出口运行受影响的完整 GUI/数据链；第9轮执行组合ON/OFF、适用ASAN、性能、隐私与视觉矩阵。第4轮和安装分发矩阵不执行。

- 当前功能总账无未批准回退；实现、正式文档和 GUI 可见行为一致。

- 性能报告至少包含 P50/P95、样本数、基准机、缓存条件、RSS/private bytes、线程/句柄和 UI 最大停顿。

## 6. 必须停下取得产品决定的门

- 是否允许解锁后的 Secure 文档正文进入外部本地模型进程。
- 本轮使用哪一份获批本地模型文件及 runtime；不安排模型捆绑分发或自动下载，本机缺少合规模型时单独提出材料/权限需求，不自行联网获取。
- 代码图首批语言及 parser 供应链；推荐先 Python、PowerShell、JavaScript。
- 是否提供远程 AI、允许的数据等级、供应商保留/训练政策和密钥存储。
- 是否持久化 AI 对话、向量或分析产物；默认全部仅内存。
- 是否另立脚本执行产品；默认永远静态，不把执行藏在“可视化”中。
- 以上AI选择在AI-D0集中确认；未获批的跨进程/远程能力继续默认拒绝，不阻塞可独立进行的设计与进程内工具。签名、发布通道不再属于本任务的决定门。
