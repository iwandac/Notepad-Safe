# 编码与换行现状

更新：2026-10-17。按当前源码记录文本/二进制判定、编码识别、重新显示、转换另存、换行符和保存时的编码行为。来源：[`FileContentProbe.cpp`](../src/editor/FileContentProbe.cpp)、[`FileTierPolicy.cpp`](../src/domain/FileTierPolicy.cpp)、[`TextEncoding.h`](../src/editor/TextEncoding.h) / [`.cpp`](../src/editor/TextEncoding.cpp)、[`EditorTab.cpp`](../src/editor/EditorTab.cpp) 的 `loadFile` 与 `detectLineEndingMode`、[`EditorTabPersistence.cpp`](../src/editor/EditorTabPersistence.cpp)、[`PlainFilePersistence.cpp`](../src/app/PlainFilePersistence.cpp)、[`MainWindowCommands.cpp`](../src/window/MainWindowCommands.cpp) 的编码菜单处理、[`MainWindowDocuments.cpp`](../src/window/MainWindowDocuments.cpp) 的 `saveFile`。

## 1. 打开时的判定

**大小分级**只看磁盘字节数：小于 32 MiB 为可编辑；32 MiB 及以上统一只读（源码里的 2 GiB 分界只是遗留分类名，两类行为相同）。

**文本还是二进制**（读前 64 KiB）：

1. 识别为 UTF-16（含 BOM `FF FE` / `FE FF`）→ 文本。
2. 出现任何 `00` 字节 → 二进制。
3. 除换行、回车、Tab、换页以外的控制字符超过 3% → 二进制。
4. 其余 → 文本。

二进制文件总是以十六进制打开；明确指定编码打开（例如转换后打开）时跳过二进制判定。会话恢复仍按内容判定，二进制即使带有保存的编码也以十六进制恢复。

## 2. 编码识别

- 支持 9 种：UTF-8、UTF-8 BOM、UTF-16 LE、UTF-16 BE、GBK（936）、GB18030（54936）、Big5（950）、Shift-JIS（932）、Windows-1252。代码页号写死，不随系统 ANSI 设置变化。
- 顺序：BOM → 严格 UTF-8 校验 → UTF-16 启发式 → 各代码页打分 → 无法可靠判断时按 UTF-8 回退，并记录“有非法字节”。
- 采样上限 1 MiB：文件更大时取开头、中间、结尾三段，不读全文。精确校验在解码、保存和转换时再做。
- 新建文档默认 UTF-8（无 BOM）。
- 解码结果带来源（BOM、校验、启发式、回退）和置信度，状态栏的编码项可显示“包含非法字节”“默认假设”等说明。

## 3. 换行符

- 打开时统计 CRLF、LF、单独 CR 的数量：CRLF 不少于其他两种取 CRLF；否则 CR 多于 LF 取 CR；否则有 LF 取 LF；都没有取 CRLF。这个结果只决定**之后新输入的换行**，不会改动已有内容，混合换行会原样保留。
- 新建文档为 CRLF。
- 编码 › 换行符转换：Windows (CRLF)、Unix (LF)、Mac (CR)。把全文换行统一改写为所选格式，作为一个撤销步骤，并设为之后的换行格式。只在普通可编辑文本可用。
- 状态栏显示编码与换行符。**没有“混合换行”的提示**。
- 视图 › 显示符号 › 显示行尾符 可显示每行的换行字符。

## 4. 以其他编码重新显示

编码菜单顶部 9 项“以 … 编码显示”，勾选项跟随当前标签：

- 加密文档和未命名文档不可用（点了也不改变）。
- 只读大文件：立即按新编码重新解释原字节，不改文件。
- 普通可编辑文本：会从磁盘重新读取字节再解码。如有未保存修改，先问“要先保存再以 X 编码显示吗？”（保存 / 取消，默认取消）；保存失败则不切换。
- 二进制文档切换显示编码只影响十六进制右侧字符栏，不改字节。

## 5. 转换编码并另存

编码 › 转换为 › 9 项，总是写一个**新文件**，原文件不覆盖：

- 不可用：加密文档、未命名文档、二进制文档。
- 若当前按某编码解码时有非法字节，先提示“请先用‘以 … 编码显示’选择正确源编码，再执行转换”，不继续。
- 只读大文件：若磁盘文件在打开后被修改、替换或删除，提示重新打开后再转换。
- 另存对话框建议名为“原名-目标编码.扩展名”，与源文件同目录；目标不能是源文件本身，也不能是另一个已打开标签的文件。
- 转换在后台任务中执行，有进度框和取消按钮；目标经原子写入。旧式编码严格转换：遇到目标编码不能表示的字符就失败，不做替换。
- 小文件转换的是**编辑器当前内容**（含未保存修改）；只读大文件按显示编码从磁盘流式转码。
- 成功后自动打开新文件，状态栏提示“已转换为 X，并打开新文件”；失败弹窗“编码转换未完成…”，附技术详情；取消不提示。

## 6. 保存时的编码

- 普通保存使用文档当前编码；UTF-8 BOM、UTF-16 LE/BE 会写回相应 BOM。
- 旧式编码严格编码：有不能表示的字符时保存失败，提示“文本包含 X 无法表示的字符。”原文件不变。
- **打开时有非法字节的文本**，保存前弹出“编码需要确认：继续保存会用当前显示文本覆盖这些原始字节”，按钮“仍以 X 覆盖”/“取消”，默认取消。选择覆盖后该编码视为用户指定，之后不再询问。二进制文档按字节模型保存，不触发此确认。
- **保存大小上限按 UTF-8 工作文本计**：保存前的快照把正文转成 UTF-8，超过 32 MiB 即失败，提示“编辑后的文本超过本次工具快照上限；请缩小处理范围。”所以一个 20 MiB 的 GBK 文本如果在编辑器中展开到 32 MiB 以上 UTF-8，能打开编辑但无法保存。这条文案也没有说明是保存失败。

## 7. 已知问题

1. 上一节的保存上限：按 UTF-8 工作文本而不是目标编码计算，且打开时没有按解码后大小降级为只读（只按磁盘字节分级）。文档中“解码展开后的大小影响只读降级”的说法与源码不符。
2. 上限错误文案写的是“工具快照”，用户看不懂这是保存失败。
3. 没有混合换行提示。
4. `setEncodingFromAction`（直接改保存编码并标记已修改）仍在源码中但未挂到菜单，属于遗留。

## 8. 新界面原型与现状的差异

| # | 差异 | 现状 | 处理 |
|---:|---|---|---|
| 1 | 编码弹出层“以其他编码重新显示” | 一致；但可编辑文本有未保存修改时会先要求保存 | 弹出层需要接这个确认 |
| 2 | 编码弹出层“自动识别”标注 | 现状有来源与置信度 | 可直接展示来源（BOM / 校验 / 推测 / 回退） |
| 3 | 换行符弹出层的“混合”提示 | 没有 | 原型新增，属于新功能 |
| 4 | 换行符弹出层文案“全部为 CRLF” | 现状不统计各类数量给用户看 | 同上 |
| 5 | 转换另存的入口 | 菜单“转换为”；原型放在编码弹出层 | 位置改动；规则（不覆盖源文件、严格转换、转换当前内容）保持 |
| 6 | 加密与未命名文档 | 重新显示和转换都不可用 | 弹出层需显示为不可用并说明原因 |
