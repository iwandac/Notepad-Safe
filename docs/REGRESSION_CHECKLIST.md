# 日用编辑器回归验证清单

2026-10-02。本清单以本次用户目标为准：像记事本一样轻便、快速、容易使用；加密文件能够离线使用并保持安全；同类阅读操作不会因为文件大小和内部模式改变而变得不可靠。依据当前源码和测试实现编制，包含尚未提交的保存与恢复修复。**本页定义128个主用例及其展开规则；实际进度和证据统一记录在执行账本，未覆盖子例保持未执行。**

[功能清单](FEATURE_LEDGER.md)记录现状，[回归方法](TARGET_EXPERIENCE.md)规定证据规则，本页负责逐项执行。现有实现不是验收答案：当前禁用、内部调用成功或旧测试通过，都不能自动证明符合体验要求。

## 验收原则和优先级

1. 先保证输入、读取、选择、复制、查找、保存、关闭重开的日常链条，再评价其他已有功能。普通文件打开不应要求建立安全身份；安全新建的首次身份建立、解锁等待单独验证，不通过静默明文回退换取速度。
2. **共同阅读功能使用同一行为和外观判据。** 相同文本片段、设置、窗口和输入应得到一致的可见内容、选区、复制内容和搜索命中。只读标识、禁止修改、全局滚动范围和按需统计可以不同，但必须准确、可理解；不能显示窗口局部行号冒充全文件行号。
3. 只读不要求恢复大文件编辑能力。修改、替换、普通保存必须从所有入口一致拒绝；仍然具备的转码输出单独验收。文件增长、编码展开、不同大小以及恢复打开，不能绕过边界。
4. wrap、语法、折叠、分屏等当前缺失的阅读能力列为体验差异，不以“只读”解释其必然缺失。本轮先闭合共同功能与已暴露控件；扩充这些能力不得偷偷引入全文装载。安全载荷上限也不因一致性目标而自动扩大。
5. 失败不能静默丢正文、覆盖另一版本、释放未保全的恢复责任或把秘密写进普通临时文件。保存提交前后、主动锁定和会话到期的失败策略分别判定。
6. 离线安全验证覆盖无联网依赖、加密存储、身份/恢复材料、锁定、临时数据和进程生命周期。它不承诺抵抗已控制当前 Windows 用户/管理员的恶意进程，也不把“扫描不到明文”当作密码学证明。

优先级决定执行顺序，不表示低优先级功能可以未经验证宣布通过：

- **P0**：正文/字节丢失或错误覆盖、秘密越界、无法退出或恢复、崩溃/不可恢复卡死。发现即阻断本版完成。
- **P1**：日常链条、共同阅读行为/外观、能力一致性、可达性和轻快指标。适用项失败必须修复或明确记录范围例外，不能用旧文档自动豁免。
- **P2**：已有辅助能力、扩展语言和低频设置。冻结清单仍需有执行结果；缺证据不计通过。

## 模式和配对样本

用实际产品打开入口确认模式，执行记录必须保存源大小、解码后 UTF-8 大小、内容身份、Provider 和 capabilities。仅测试内部 `openSurface(windowed=true)` 不能代表正常打开路由。

| 代号 | 实际模式 | 主要比较对象 |
|---|---|---|
| T | 普通小文本，完整 QScintilla | RT 的相同文本片段；ST 的非安全交互 |
| BH | 小二进制 Hex，可编辑字节模型 | RH 的相同字节片段；SH |
| BT | 小二进制 Text 只读投影 | 同编码 RT/二进制 Text 投影；BH 字节身份 |
| RT | 普通文本窗口化只读 | T；相同内容的不同只读大小 |
| RH | 普通二进制窗口化只读 Hex，可切 Text | BH；RT 的共有阅读控件 |
| ST/SH | 解锁安全 Text/二进制 Hex，小载荷 | T/BH；安全二进制切 Text 仍按投影边界 |
| SL | 已锁定或锁定转换中的安全文档 | 无读、复制、搜索、修改能力 |
| A/E | Accounts/空工作区 | 焦点、命令归属、空态与秘密隔离 |

当前普通可编辑准入是有效大小严格小于 32 MiB，2 GiB 不是功能分界。安全载荷也必须严格小于 32 MiB；测试以解密正文尺寸判定，不能按压缩后的 KDBX 文件大小判定。

| 夹具代号 | 确定的构造和真值 |
|---|---|
| TXT | 64 KiB 基准正文：唯一头/中/尾 marker、重复词、大小写、Tab、空行、中文/emoji/组合字符；保存独立期望文本、UTF-8 字节和 marker 范围。另有所有旧编码可表示的共同子集 |
| SIZE | 将 TXT 的相同锚点片段放进 32 MiB−1、32 MiB、32 MiB+1、64 MiB、256 MiB、2 GiB+、4 GiB+ 文件；填充不产生目标命中；各自记录全局范围，不能假定偏移/总行数相等 |
| EXP | 磁盘小于 32 MiB、独立解码后的 UTF-8 大于等于 32 MiB 的 UTF-16/GB18030 文本；与同内容 UTF-8 配对，确认实际路由 |
| ENC | UTF-8、UTF-8 BOM、UTF-16 LE/BE、GBK、GB18030、Big5、Shift-JIS、Windows-1252；可表示与不可表示字符分开；附非法/截断序列，不用产品编码函数产生期望值 |
| EOL | LF、CRLF、CR、混合行尾；有/无末尾换行；空文件、单行、重复行；保留逐字节期望 |
| WIN | marker/多字节字符/CRLF 放在投影边界前、边界上和边界后；当前 Text 1 MiB、Hex 256 KiB 只是夹具定位参考，执行时核对实际窗口和可见范围；另有超过窗口的单行 |
| BIN | 0/1/15/16/17 字节与 00..FF 模式，含有效/非法多字节序列；另制 SIZE 大小样本；每次变更的期望字节由独立数组计算 |
| HIT | 无/单/多/密集命中、零宽/跨行/捕获、200000/200001 命中；在生成时记录有序 byte range，包含尾部和超过 32 位的偏移 |
| SEC | 独立合成身份、密码和恢复密钥；安全 Text/Binary 的 0/1、32 MiB−1/等于/+1 解密载荷；高可压缩内容及中文 UTF-8 膨胀；秘密 canary 不复用真实资料 |
| FAIL | 本次 profile 下目录被文件占用、文件共享限制、写入/提交/重开故障、损坏/未来版本清单、源删除/截断/同大小替换；记录故障注入层与真实 OS 失败的区别 |

所有夹具记录生成参数、seed、实际字节数、SHA-256、编码、行尾、独立预期。稀疏文件记录 allocated size，不能证明真实磁盘吞吐；大文件只生成本次必要样本，禁止复制或改写用户真实语料。破坏性故障和强杀只对本次 PID/profile 操作。

## 组合展开规则

- 每一行是一个稳定 CaseId；行内有多个参数时，展开为 `CaseId/模式/夹具/输入/布局/故障阶段` 独立子例。某一子例通过不得把整行涂绿。
- P0 的每个阶段、每个安全触发原因、每个大小边界都展开；前一项成功/后一项失败的顺序反转也要覆盖。成对抽样不能替代这些边界。
- 共同 Text 行为至少做 T↔RT、RT 的 32 MiB↔256 MiB；共有字节行为做 BH↔RH、BT↔窗口化 Binary Text。大偏移对阅读/定位/搜索另跑 2 GiB+/4 GiB+；不把所有编辑功能重复在不适用的大文件上。
- ENC 全部编码都跑打开/显示/复制/搜索字面量/适用转码；完整正则与原编码受限子集分开，支持交集的匹配必须一致，不能静默改变语义。
- 第一轮共同行为固定两个视图设置：Light/1400px/100% 与 Dark/900px/150%，键盘和鼠标均覆盖。外观按本页17组固定组合展开，另做跨显示器切换；记录组合与未覆盖项，不能只写“做过 pairwise”。
- 必跑三因素：非 UTF-8×跨窗口选区×Text/Hex；分屏次视图×行操作×Undo；只读×全选超限×原剪贴板；安全搜索×锁定×保存失败；多稿×清单失败×重启；超长行×远跳×主题/缩放变化。
- 所有可切选项至少有默认值、反值、返回默认值的判别样本。状态变更后再执行第二次操作，核对焦点、dirty、revision、选区、任务和磁盘；不只截一次屏。

本组每例同时记录两个实际模式的结果，并在共同锚点处截图和核对内容；不能只测试 RT 自己。允许 gutter 随真实行号位数增长、滚动滑块随全文长度变化、只读状态提示不同，不要求这些几何数值逐像素相等。其余共用样式应使用相同字体、颜色和交互规则。

## 离线安全与秘密生命周期

网络观察绑定测试进程和子进程；离线隔离优先使用测试环境，不关闭共享主机网络。到期/时钟回退用可控测试时钟或隔离 VM，不修改共享主机时间。真实锁屏/睡眠在明确交接后的隔离环境中测试。观察能力不足时记录受阻，不以源码无网络类代替动态结论。

canary 扫描限定本次 profile、进程实际写入的临时位置、日志及保全目录，检查 UTF-8/UTF-16LE/BE 和相关序列化形式。文件名、标题、路径、最近列表等元数据另行记录；不要把正文保密外推成所有元数据都加密。在本次检查的持久化输出和可观察UI/剪贴板范围内，明文仅允许出现在用户明确选择的导出文件或当下解锁界面/授权剪贴板中。解锁期间编辑、解密、搜索必需的进程内明文不作不存在承诺，锁定后的已知缓存另行验证。产品重新打开与独立读取/解密、已知明文对照共同构成判据。

下列“历史门”取自[原始性能记录](ROUND3_PERFORMANCE_RECOVERY_ACCEPTANCE.md)，本次保留为候选复验标准，不表示已经通过。小文件打开/保存、加密解锁、CPU/内存绝对预算缺少可信的已批准数值，先记录基线与明显退化，不临时发明一个绿色阈值。历史首paint P95 693.458 ms 对应旧候选，既不能迁移为本轮测量，也不能抹去原500 ms未通过结论。

每个统计场景先校验一次观察器，再冻结30个独立样本的条件与次序；报告首轮、重复轮次、P50/P95/max、失败与无效原因。没有受控缓存协议不称冷/热启动。P95用预先固定的nearest-rank（排序后第ceil(0.95×N)项）复算，保留原始样本；若与历史算法不同必须并列，不能直接比数值。截图/观察器开销保留而不随意扣除；观察无效既不是产品通过，也不能直接当产品失败。

分母与补样规则：产品超时、崩溃、错误内容是失败，不能改标观察器无效后排除；有此类失败时不宣布整组通过，成功样本分位只能作辅助。计划轮数、产品失败数、观察器无效数、统计有效数分开报告；不足30个统计有效样本不宣称P95门通过。只对有证据的观察器无效补样，原因、次数上限、补样次序测前固定，保存全部原计划和补样，不择优挑30轮；超时没有完成时间时保留延迟下界，不填零。

## 当前差异与验收处置

这张表区分已确认的实现差异、静态风险和运行证据；不是新增Bug的复现报告。

| 差异 | 当前源码依据 | 本轮处理 |
|---|---|---|
| Tab宽/长行标尺对只读表面更新不同 | `EditorTab::setTabWidth`、`EditorTab::applyEdgeSettings`只更新原生/分屏对象 | PAR-06优先验证；已暴露的共同设置不生效按P1缺陷，不接受仅菜单变化 |
| 书签可能作用于隐藏对象 | `EditorTabCommands`直接使用`m_editor`，只读仍有书签入口 | PAR-27优先；必须功能有效或如实说明范围，不得静默无效 |
| 排序对换行/副分屏/Undo存在风险 | `sortLinesAsc/Desc`直接取`m_editor->text(line)`并拼接换行 | EDIT-06/08先建立判别例；未运行前只称风险 |
| 普通SaveAs菜单与底层能力不同 | `CommandRegistry::applyContext`按有文档启用；保存层再拒绝只读 | PAR-08/SAV-03要求所有入口一致反馈，转码命令独立 |
| RT无自动换行、全局光标行列 | wrap强制关闭；状态栏为浏览偏移，gutter按需得到全局行号 | PAR-18/26列核心阅读体验差距；当前位置不得冒充光标。先评估有界实现，未满足就单列，不能以旧拒绝测试判一致 |
| RT无语言/折叠/括号/分屏 | 原生表面能力门控制 | PAR-28/29验证限制可理解、T不回退；增强阅读能力登记范围差距，本轮不因此全面换内核 |
| 非UTF原编码正则子集不同 | `EncodedRegexCompiler`受限编译 | 支持交集须一致；不支持节点精确拒绝并给可行路径；不能只复用UTF-8结果 |
| 全选/复制与统计存在成本边界 | 64MiB级复制预算、异步行数/字符统计、只读搜索全文件映射 | PAR-12/17/19及PERF-05/07要求透明反馈、准确最终结果、资源可测，不隐藏截断 |
| 只读安全副本受保存/安全载荷限制 | 只读普通另存拒绝；安全正文严格<32MiB | 不要求本轮突破安全上限；SAV-03核对说明和可用出口，列能力差距，避免用户误以为任何可读文件都可加密保存 |
| 保存/恢复不是整体事务 | 末次检查至commit窗口；draft可同路径更新后manifest失败 | SAV-04/06、REC-02/08按真实磁盘阶段验收，不写“任何失败全回滚” |
| 已打开普通文本增长的上限不一致 | 快照以`>32MiB`拒绝，恢复稿以`>=32MiB`拒绝 | EDIT-11核对等于/越界状态，不能只测文件打开降级 |
| 会话读端有容量限制，写端需往返核验 | `SessionManager`读取限制256项/4MiB，写端未见相同发布前拒绝 | REC-09核对产品自生成输出，不能仅测拒绝恶意超限输入 |

“不适用”只用于语义上不合法的组合，例如只读正文插入的成功用例（另有拒绝用例）、锁定文档复制成功、Binary原字节正则替换。实现缺失、测试工具做不到、缺桌面、没时间均不能标不适用。产品边界可明确登记为限制；整体结论同时报告一致性达成程度，不用“现有限制”掩盖差距。

差异类子例必须记两个结果：**限制表现**（禁用/提示/数据保留是否正确）和**模式一致性**（达成、未达成、未验证、无可比语义）。PAR-18/26/28/29和SAV-03的限制表现可以验证通过，但只读缺失能力的一致性仍未达成；不能因完成差异登记就将整行标为一致。书签等若通过禁用入口处理，也必须保留失去阅读能力的差距。范围例外不等于一致性通过。

## 执行规则和完成标准

执行顺序仅维护在 [统一回归计划](ITERATION_ROADMAP.md)，本清单不另设一套批次。每个主用例所需的Core、Qt、GUI及正式进程证据都属于同一项；GUI、重启/强杀或安全生命周期尚未验证时，不能先宣布该项完成。受控性能测量在功能修复稳定后统一执行。

优先反例：PAR-06/08/10/12/18/27，EDIT-06/08/11，SAV-06/09，REC-02/03/04/09，SEC-09/10/11/17。先完成VAL的真实路由、独立byte/range判据和样本身份；测前记录预期，不按实际输出倒填。一次执行可关联多个ID，但必须覆盖各自前提与断言；失败在原用例下修复并做相邻复测，不能只刷新总通过数。

功能正确性、只读一致性、离线安全、轻快性能分别给结论。无P0开放缺陷，P1适用项有可信结果，范围差异和P2未完成项公开。未执行/受阻不是通过，性能例外和核心体验缺口不自动从清单删除。GUI与BD2明确交接，性能另外要求低干扰窗口；结束后归还桌面。

每次运行新增一条记录，保留前次失败，不覆盖历史。最小字段：

```text
CaseId / 子例参数 / FeatureId / 优先级
源码HEAD + 工作树差异摘要 / 配置 / 产品与测试EXE哈希
fixture参数与SHA-256 / 实际模式与capabilities / 初始revision及磁盘基线

```
