## 1. 本轮要交付的用户结果

本轮不是增加一批菜单，而是让同一个文件从不同入口进入时得到同一个、可理解、不会互相覆盖的结果：

- 用户已经打开 Notepad Safe 时，再双击或从命令行打开文件，文件进入现有窗口；不会再启动一个与它争抢会话和恢复数据的进程。
- Ctrl+O、拖放、命令行、最近文件、会话恢复和搜索结果导航共享同一个文件识别、能力、编码、Presentation 与持久化真值。
- 查找结果明确说明“在哪里找到、是否完整、为何停止”；取消、文件变化或目标关闭都不会把旧结果导航到新内容。
- 查看持续增长的日志时，用户可以选择“跟随文件末尾”；向上浏览会暂停跟随，用户明确选择“回到末尾”后才继续。
- 界面只说明用户能做什么、为什么当前不能做以及下一步是什么，不泄漏 `S1/S2/S3`、`B1/B2/B3`、Provider、projection、mmap、task id、revision 等工程词汇。

## 2. 不在本轮内

- 不改变 `<32 MiB` 可编辑、`>=32 MiB` 永久只读的固定边界。
- 不增加目录搜索、Hex Replace、脚本执行、AI、云同步或协作。
- 不用数据库或独立服务解决单实例；产品仍是一个本地桌面进程和一个安装单元。
- Tail 只跟随普通只读文件的增长，不自动重开被替换的安全文档，不绕过外部变化冲突处理。
- 不把所有 UI 文案重写一遍；只收敛本轮旅程及所有会向普通用户暴露内部实现的高风险文案。

## 3. 切片 2A：单实例与外部打开

### 设计

第一个进程是唯一会话写入者。后续进程只把规范化的打开请求交给第一个进程，收到确认后退出。传输内容只能是动作和文件路径，不含文件正文、选区或安全凭据。Windows 路径身份必须处理大小写、分隔符、相对路径和符号链接/重解析点可获得的最终身份；同一文件只打开一个标签并激活它。

所有权与转发采用两个互不替代的原语：

- `QLockFile` 位于解析后的当前用户数据目录，是唯一会话写入权的事实来源。应用必须在构造 `MainWindow`、`SessionManager` 或任何恢复/保存对象前取得长期锁，并持有到进程退出；权限错误或锁状态不明时失败关闭，不能启动第二个会话。
- `QLocalServer` 只承载同一 Windows 用户的有界、版本化请求，不承担唯一所有权。Windows 允许同名命名管道存在多个 server instance，因此 `listen()` 成功不得解释为取得主进程身份。
- Windows 正式 GUI 进程不得依赖 GUI 线程的命名管道事件通知。`QLocalServer(UserAccessOption)` 及所有已接受的 `QLocalSocket` 必须完全归属一个专用 I/O 线程；该线程使用有上限的阻塞 accept/read/write 处理一帧请求和一帧响应，不使用 GUI 线程轮询。
- I/O 线程只能向主线程交付已校验的绝对路径列表或激活动作；不得访问 `MainWindow`、`SessionManager`、文档正文、凭据或任何持久化对象。主线程未完成会话恢复时，请求仍由主线程的现有有界队列保留。
- ACK 的唯一含义是“请求已原子地进入协调器的有界待交付队列”，不代表文件已经打开，也不能只因为 I/O 线程发出过信号就返回成功。该队列最多保留 32 个请求、256 条路径和 512 KiB UTF-8 路径数据，任一上限超出时必须在入队前以 `request_queue_full` 拒绝，不得 ACK。
- 协调器在主线程明确标记“会话恢复完成、可交付”前一直保留上述队列；开始交付后按入队顺序在主线程发出请求。不再另建一个无界的恢复期队列，且窗口/会话对象永远不进入 I/O 线程。
- 启动只在 I/O 线程回报“已监听”后才能构造会话写入对象；监听失败则释放锁并失败关闭。所有可取消的关闭确认通过后、最终会话保存前，先原子关闭请求接收门，等待 I/O 线程终止，再在主线程同步交付已经 ACK 的请求；最终保存及窗口/会话析构完成后才释放 `QLockFile`。不得 `TerminateThread`、遗留孤儿线程或在 socket 未完成时销毁其所属对象。
- 每个连接的请求读取上限为 2 秒，等待 ACK 的客户端总预算为 5 秒；最多同时保留 8 个连接，单帧和路径数量/长度仍受协议上限约束。连接必须使用同一 I/O 线程内的独立状态与 deadline 多路复用，不得用串行 `8 × 2s` 阻塞把合法客户端拖过总预算。任何超时或关闭竞争都必须收敛到线程终态，不得越过锁启动第二个会话。
- 线程创建和 join 必须由 `src/async` 的最小专用线程封装承担，`src/app` 不得直接创建 `std::thread`、`QThread` 或私有线程池；长驻 IPC 也不得占用通用任务线程池的工作槽。
- 响应帧只接受协议定义的 `version/status/code` 组合；未定义字段、缺失必需字段、错误类型、追加字节或第二帧一律失败关闭。
- 持锁进程尚未开始监听时，后续进程只能在有界时间内等待同一端点；持锁进程崩溃后，新进程必须通过锁文件的 PID/进程身份陈旧检测重新取得同一把锁，再成为主进程。
- 长期锁使用 `setStaleLockTime(0)`；不得只按锁文件年龄强行删除，也不得在仍有有效 owner 时提供自动“忽略并继续”。

### 失败方式

- 主进程尚未开始接收：后续进程在有界时间内重试握手，而不是抢写 session。
- 主进程无响应或协议版本不兼容：后续进程显示可理解错误并以非零状态退出；不得偷偷成为第二个会话写入者。
- 路径不存在、不可读或类型不支持：错误在主窗口呈现，已有文档不受影响。
- 攻击者伪造本地消息：只接受当前 Windows 用户、带版本和长度上限的请求；拒绝正文和未定义动作。

### 验收

- 启动正式 `notepad-safe.exe` A，再启动 B/C，分别传入同文件的相对路径、绝对路径和大小写变体；最终仅 A 存活、仅一个标签、只写一份 session。
- A 正在恢复会话时接收外部文件；恢复顺序与外部请求均不丢失，活动标签结果确定。
- A 脏文档的正文、修改状态和源文件保持不变；既有搜索不被取消或清空。运行中的“全部打开文件”搜索保留既有动态纳入新文档的语义，原目标结果不得丢失；已经完成的搜索结果不因外部打开而重跑。
- 当前为 Accounts 或其他辅助工作区时，普通外部文件只后台加入文档标签，不切换工作区或已有当前标签，不释放账户工作区秘密，不改变筛选、选中项和安全会话。文档工作区内的外部打开仍正常激活目标。
- 外部安全文件只显示“请在窗口内用文件→打开”的提示，不检查正文、不触发解锁；任何外部打开都不触发保存或网络。
- 强杀 A 后能够由新进程取得所有权；陈旧端点不造成永久无法启动。

## 4. 切片 2B：入口一致性与产品语言

### 设计

所有真正打开文件的入口复用现有类型化请求、文件探测、DocumentSession 和 Provider/持久化路由，不新增一套平行打开框架。入口不得自行猜测 Text/Hex、编码、大小等级或持久化适配器。普通重复打开使用同一个文件身份判断并复用已有标签；外部请求的展示/安全授权仍遵守 2A。搜索结果是对已有 `DocumentId + revision + byte range` 的导航，不重新探测或打开另一份文件。

恢复记录携带关闭前的展示意图，不等同于一次无参数的新打开：有效的编码、语法和 Text/Hex 选择必须保留；文件的当前大小/只读能力和持久化安全边界仍由现有事实来源决定。未保存恢复稿是独立的数据恢复权威，不能以普通文件去重为由覆盖或丢弃。

#### 2B1：先闭合普通文件恢复（受影响 FeatureId：NSP-FILE、NSP-SHELL、NSP-ENCODING、NSP-LANGUAGE、NSP-VIEW）

- 对已有编码名称做有界、精确的受支持值解析；有效名称在打开前传入现有 `DocumentSurfaceOpenRequest`。空值或未知旧值回到既有自动探测，不猜代码页、不改变会话格式版本。
- Binary 的内容身份与 Text/Hex 呈现分开；恢复显示编码不能把 Binary 改判为 Text，不能让 B2/B3 变成可编辑，也不转换源字节。
- 会话中的有效语法选择在成功恢复后统一应用，包括 clean 原文件与恢复稿重试；不因扩展名自动识别覆盖手选语言。
- clean 原文件只指 `modified=false` 且无恢复稿引用的普通记录，恢复前复用统一普通文件身份判断。如果同一物理文件已由本次显式打开请求建立标签，则复用该标签且保留其当前状态和优先活动地位，不再创建第二份状态；此规则不用于丢弃 dirty 恢复稿。`modified=true` 但恢复稿路径缺失/无效仍是未保存恢复失败，不能悄悄加载磁盘原文件报成功。
- 当前路径属于安全持久化适配器时，旧记录的 `secureDocument=false` 不能把它送入普通可编辑 Provider，也不能把 dirty 恢复稿重新绑定为可直接覆盖该安全路径的 PlainFile。clean 和 dirty 的初次恢复及 Retry 都必须检查这一边界；失败时保留对应待处理页及原稿，给出显式重新打开的下一步，不允许静默解锁。
- missing/不可读/类型变化的 clean 恢复不能计入“已恢复”成功数；复用现有失败页外观，但以显式 OriginalFile/UnsavedDraft 状态区分原文件重新打开和未保存稿恢复。OriginalFile 提供“重试打开/移除标签”，移除只删会话待打开项，不调用恢复稿删除；UnsavedDraft 保留“重试恢复/确认放弃”的原有受管删除边界。两者均明确原文件未改动及下一步，不得用成功总数隐藏失败。
- 缺失恢复稿的界面不得声称“恢复稿仍保留”；通用摘要只承诺原文件未被本次恢复修改、未保存内容尚未恢复，具体存在/损坏/缺失由真实原因说明。确认放弃不等于承诺磁盘上仍有可删除的稿件。
- 汇总只统计实际解决的文档和未解决项；去重后仍能把保存的活动项映射到正确文档/失败页，不能继续用发生漂移的原始列表下标选择标签。启动显式打开的优先活动地位保持不变。

必须使用下列用户语言结构：

| 内部事实 | 用户可见表达 |
|---|---|
| 文件超过编辑上限 | “此文件较大，已以只读方式打开。你仍可浏览、查找和复制。” |
| 二进制内容 | “这是二进制文件。你可以查看十六进制字节；只有较小文件可以修改。” |
| 搜索被取消 | “已停止查找；已找到的结果仍可查看。” |
| 文件在搜索中变化 | “文件已变化。请重新查找以获得准确结果。” |
| 外部保存冲突 | “磁盘上的文件已被其他程序修改。请选择保留当前内容、重新载入或另存一份。” |
| 恢复点不可用 | “无法恢复未保存内容；原文件没有被改动。” |
| Tail 暂停 | “已暂停跟随，你可以继续查看上方内容。” |

文案可因上下文缩短，但必须包含“发生了什么、还能做什么、下一步是什么”三者中适用的部分。

#### 2B2–2B3：入口反馈与默认界面语言

- 混合拖放请求不得静默丢弃不存在的本地路径：有效项照常打开，失效项给出真实原因和下一步；不处理远程 URL，也不扩大外部安全文件授权。
- 默认可见的状态、提示、恢复页和任务详情不暴露 `S1/S2/S3/B1/B2/B3`、`mmap`、`overlay`、`patch`、`Scintilla`、`Provider/Adapter`、内部诊断码或“低价值全文扫描”等实现评价。显示名称优先使用“文本/二进制/十六进制/只读”；技术诊断可以保留在用户主动展开的“技术详情”中。
- 不删除有价值的错误原因来通过词表；对默认摘要使用产品语言，原始诊断保留在可选择的技术详情或本地日志。禁止把所有失败改成同一条无下一步的泛化提示。
- 2B 只收敛搜索终态的表达与可访问性，不改变 2C 的结果身份、过期判定或完成度算法；Tail 的行为实现和完整验收留给 2D。
- 运行时语言门禁枚举受测状态下实际可见的菜单、Label、按钮、状态栏、tooltip 和 accessible name/description；不把日志或用户文件正文算作产品文案，不以扫描源码字符串代替可见 UI 验证。

具体收敛决定：

1. 拖放以本地 URL 意图接收，不能在 MIME 提取层按 `isFile()` 丢失失败项。使用现有外部打开通道分别处理有效、缺失、目录、不可读和安全文件；有效项不被其他失败阻断。远程 URL 不读取、不下载。错误明确路径和适用原因，不能凭打开失败猜测权限错误。
2. 状态栏用“文本 / 二进制”“文本视图 / 十六进制”“可编辑 / 只读”。大小数值保持既有权威：普通已保存 S1 是打开/上次保存时的文件大小（不含未保存修改，也不承诺磁盘实时值）；窗口化只读文件是当前读取视图的源大小；可编辑 Binary 是当前字节内容大小；未命名/安全文本的内存值按 UTF-8 计，不称保存后文件大小。用各自准确的 tooltip/读屏说明区分，不为统一文案改变 `contentSizeBytes()`、路由等级或增加全文编码计算。只读说明保留浏览、查找、复制。Binary Text 不提供全文字符总数，明确说明这一限制，不评价实现为“低价值”。
3. `OVR/INS` 是已具备中文 tooltip 和读屏说明的标准编辑模式缩写，本轮保留；语言名称、编码名、KDBX 文件格式和用户内容不是实现术语，不能被禁词门误删。门禁对产品字段检查，不对用户文件名、查询或正文做全局替换。
4. 后台任务默认保留任务名称、状态、当前阶段、准确百分比和有效的预计剩余时间。优先级、线程占用、ID、原始计数、精确时间、描述和堆栈进入默认折叠的“技术详情”。线程数仍是线程数，不能改名成任务数；活跃任务数是排队/运行任务数，不是其中可取消的数量。“取消所选”与行内取消共用真实 cancellable 能力，不能在不可中断阶段显示可点击却无效的取消按钮。展开动作可键盘操作；折叠时读屏摘要不得转述隐藏诊断。
5. 任务失败使用明确的用户原因和下一步，技术原文完整保留。已有 `AsyncErrorInfo.message` 未承诺可直接展示，且可能是异常或 `QFile::map` 信息；不能直接把它截成第一行当产品说明，也不能按错误中的英文子串猜原因。最小实现可以给已知错误生产点增加用户说明，未知异常如实说明该任务未完成、可查看详情后重试，不伪称文件或恢复稿必然无变化。字符总数为负不等于仍在统计：只有既有 Provider 的 pending 为真才显示“统计中”，其余未知值说明“暂不可用”；不新增独立状态或推测失败类型。
6. 任务自绘行、选中摘要和读屏角色应共享实际展示文本；语言测试必须覆盖自绘字段，不能只枚举 `QLabel`。选中任务继续运行时，摘要应随真实状态/阶段更新；不能要求用户重新选择才看到结果。任务完成时既有 model reset 会把任务移入历史，必须按稳定 TaskId 重新定位所选项，而不只是监听 dataChanged。保持现有进度精度、阶段顺序、取消能力和完成状态不变。
7. 恢复页在 2B1 两种状态基础上增加默认折叠诊断；默认原因按真实缺失、损坏、源变化或当前安全类型给出。不能仅隐藏诊断后留下相同泛化摘要，也不得改变 Retry/Remove/Discard 的数据边界。
8. 搜索中按字节分组的展示称“预览片段”，不称“字节窗口”，也不冒充真实文本行数。完成、停止、部分、变化和关闭都保留既有真实计数与状态；原始不完整原因进入技术详情，默认保留可理解原因/下一步。组节点 tooltip、即时状态栏和读屏也属于默认展示，不能从旁路重复隐藏诊断。所有摘要更新同步到“查找状态”的读屏说明。不得在仍收集结果时写“查找完成”。
9. 2B2 明细截图中的 Qt 默认 `OK / Show Details / Hide Details` 仍是英文，本片将本轮新增/改动对话框的这些操作改为可理解的中文，并保持原有键盘与展开/收起行为；不为此升级 Qt 或扩展到全项目国际化重构。

验收先用失败任务含源码位置/内部术语、缺失稿、只读 Binary Text、搜索各终态和混合拖放建立红灯；随后复跑现有精确进度/取消、恢复数据保护、外部打开状态保留和搜索行为回归。对工程词汇的默认隐藏及主动展开分别断言，并检查实际截图，不以改松旧断言换取通过。

2B2 的最小开发切片限于拖放意图和外部打开反馈，不同时改写任务面板：

- 缺失路径、目录路径仍是本地文件打开意图，应被接收后说明不能打开的原因；不遍历目录。只含远程 URL 的拖放不受理，不访问网络、不把 URL 当正文插入。
- 验证主窗口和编辑区的混合拖放：有效普通文本/二进制照常打开，缺失和目录有反馈，安全文件不解锁；已有 dirty 文档、源文件 hash、只读能力和重复文档身份保持不变。复用既有 Hex drop、最近文件身份和 2A 工作区回归，不重写全矩阵。
- 多项请求的失败和安全拒绝不能被随后成功项的状态提示完全覆盖。反馈必须能辨认未打开的文件和下一步，但不引入新的通用打开服务或消息框架。
- 反馈承载固定为本次批次的一份失败记录：有普通打开失败时，全部项处理完后沿用标题为“错误”的一次汇总对话框；只有安全拒绝时保持非打断提示，不自动弹窗或切换工作区。状态栏提供可键盘聚焦的“未打开文件（N）”复查按钮，用户主动打开同一份只读明细（路径、原因、下一步），避免长路径/多项被状态栏裁掉。只保留最近一次外部批次的记录，不做消息历史或持久化；新批次替换记录，空批次不清空它。该按钮不执行重开或解锁。
- 外部请求的拒绝解锁权限必须到统一打开的最终路由仍然有效，不能只依赖入口较早的一次路径探测。若测试证实两次探测间文件类型变化可进入凭据流程，应在既有打开调用上携带明确授权策略并再次拒绝；不得用当前工作区或 Text/Hex 呈现猜测授权。

### 验收

- 同一组 Plain Text、Binary、Secure、Accounts、B2 和 B3 fixture 经适用的 Ctrl+O、拖放、CLI、最近、恢复与搜索结果入口核对 Presentation、能力、编码和保存适配器。同一会话重复打开要求复用 DocumentId；新会话不要求随机 UUID 恰好相同。Secure 的外部入口拒绝与显式窗口内打开分别验收，不把授权差异当作不一致。
- 2B1 红灯必须包含 Binary Text 手选 Windows-1252 后真实恢复、普通文本手选语言后 clean 恢复、启动 CLI 与 clean session 指向同一文件/别名，以及 missing/安全适配器与旧会话标志矛盾的失败关闭；逐项断言源文件 hash 未变化、没有新增 dirty 状态、只读能力未扩大。
- 自动扫描所有可见菜单、状态栏、对话框、Toast、任务面板和恢复消息，禁止内部词表；随后进行中文默认界面的人工视觉复核。
- 键盘与读屏能够读出只读原因、搜索状态、Tail 状态和错误后的下一步；颜色不是唯一状态载体。

## 5. 切片 2C：搜索真值复核

### 设计

搜索结果身份绑定 `DocumentId + revision/source identity + byte range + query options`。结果面板必须区分完成、部分、取消、过期和失败；不能把“有若干结果”隐含成“已搜索完整文件”。双击过期结果不得猜测位置，必须提示重新查找。

### 验收矩阵

- 文档：S1 文本、B1 Hex、B2 文本/Hex、可用真实 B3；编码覆盖 UTF-8、UTF-16LE/BE、GBK 与含解码错误内容。
- 查询：大小写、全词、产品正则、Hex 字节；Next、Previous、wrap、Find All、取消。
- 生命周期：搜索中切标签、关闭目标、编辑目标、外部 append/truncate/replace、连续发起两个查询、关闭结果面板后重开。
- 数据证据：命中 byte range 与独立扫描 oracle 一致；导航显示文本/字节与源范围一致；取消后的结果数量和完整性标签一致。

### 2C 预审收敛（尚非运行验收）

现有 `tc_fr_007/010/014/027–030/032/037–040` 已登记动态 All Open、S1 取消重跑、编辑失效、64 位定位、spool 成功尾页及 UTF-8 错字节/多编码快照；不以重写同类测试代替补齐以下边界：

- 排队跳转在实际提交选区前再次校验目标身份/revision；测试在真实双击发出请求后、排队跳转前修改内容，旧范围不得应用。
- 单文件 A 查询迟到完成不能污染切标签后开始的 B 查询；拒绝启动和取消也必须成为对应查询的明确终态。复用现有查询代次权威，不额外建立一个平行搜索管理器，也不改变 All Open 动态纳入新标签的语义。
- 排队但尚未进入 worker 的搜索取消也必须结算：通用任务管理器会直接把 Queued 任务记为 Canceled 并跳过业务 worker，搜索不能只等待 worker 内的回调。用真实普通线程池被受控任务占用、再由界面发起/取消 L1 与已准备好读取源的 L2 查询验证；零结果仍有明确停止状态，可立即重新查找。只读源码已发现这一路径缺少业务收尾，尚待红灯证明，不在 2B3 提前修改任务调度。
- 同一路径还必须验大文件搜索的保留计数：`findAllViaTaskManager/findOneViaTaskManager` 在提交前取得 reservation，若已取消 worker 被跳过，当前 worker 内的释放 guard 不会运行，`stopWorkers` 可能持续等待。L2 红灯应由独立进程 deadline 隔离；不能靠用户超时强杀冒充正常关闭。修复须原子区分真正未开始与已经进入 worker：不能依据可能迟到的 UI Queued 状态提前释放仍在使用的源，也不能让所有已取消业务 worker 无条件照常执行。继续复用现有搜索生命周期、mutex/CV 与单次结算，不建立通用第二套调度器。
- L2 排队取消的独立进程测试分 Find All/Find One × cancelAndWait/真实关闭文件四场景；先真实预热只读搜索源，再以实际 worker entered 与各优先级 canary 验证确实排队。父进程拥有临时目录和源 hash，只终止自己的超时子进程；收到停止前数据守卫后计有界 deadline，超时仍是失败。绿色还须销毁目标后再释放负载，证明迟到回调不访问旧源。此项测试准备不意味着 2C 已执行。
- 非取消的扫描/临时存储失败须同时结算领域结果与通用任务状态。当前 Find All worker 的 reportError 未被使用，失败仅发出领域 failed，存在任务面板仍显示完成的源码风险；2C 用真实失败注入验证并修复这一结算路径。2B3 只增加用户说明，不把展示文案修正冒充任务生命周期已修复。
- 结果上限应保留有界且可阅读的部分结果，并说明“至少 N 处、未查完”和缩小查询的下一步，不把资源上限说成完整零结果。边界测试分别为刚好 200,000 条及 200,001 条；不能因为刚好达到容量就谎报“超过上限”。确需判定还有更多命中时，只允许有界的额外哨兵命中，不提高结果驻留预算。
- 部分 Find All 的前 N 条不能标为完整的方向查找缓存。Next/Previous/wrap 仍能找到结果上限以后的真实命中；新增查询后迟到完成也不能回填当前查询的 highlights/cache。S1 的 literal 与 regex 分别验收容量边界，不用只改回调显示掩盖扫描器提前截断。
- 外部 append/truncate/同长度原子 replace 的窗口重映射已有覆盖，但 Dock 完成度与旧结果导航仍需 GUI 验收。沿用 `DESIGN.md` 的条件：只有证明同一身份且已扫描前缀未变，才可保留旧前缀范围并标明该范围；无法证明时保守失效，不把旧全文件完成计数沿用到增长后的文件。本片不实现 Tail 增量搜索。
- 补 UTF-16LE/BE 和 GBK 畸形字节的实际 Next/Previous/wrap/Find All 与双击源范围，不重复已有合法编码或非法 UTF-8 全矩阵。L2 首批结果后的取消、隐藏/重开结果面板和立即换查询另做终态检查。

上述是源码预审发现和待验行为，不是本轮已复现/已修复结论；仍须先红灯，再最小实现和主代理独立验收。

### 2C 外部源准入合同（2026-08-30，待开发验收）

释放闲置搜索映射只解决资源占用和重跑读取范围；不能据此宣布外部源安全已闭合。后续片复用现有注册路由、DocumentSession revision 与 Provider 轮询，落实以下条件：

- 500 ms 观察只捕获文件身份/大小/mtime；同大小、保 mtime 的原子替换也须识别。不每次读取保存冲突的最多 192 KiB 内容样本。

- 保留已注册格式识别语义，未知安全格式/未知版本是否扩大拒绝另行决定；本片不引入网络、模型、解密或新的用户授权。

## 6. 切片 2D：大日志 Tail

### 设计

Tail 是只读大文件视图的显式开关，默认关闭。开启时仅在用户仍位于末尾附近且文件以同一身份追加时跟随。任何向上滚动、选择上方内容、搜索跳转或 Go To 都立即暂停；界面显示固定的“回到末尾”动作。文件截断、替换、删除或不可读时停止 Tail 并解释原因，不自动抢回位置。

Tail 不做全文轮询复制：复用现有文档级外部变化观察与按需读取，不新建平行 watcher/轮询。关闭 Tail 撤销跟随及迟到定位，不停止文档级的外部变化检测和搜索失效通知；关闭标签/退出才释放文档观察器和 timer。Tail 专属活动在关闭 Tail 时释放。应用位于后台或文件长期不变化时不得产生持续高 CPU。

### 2D 预审收敛（尚非运行验收）

- 状态收敛为关闭、跟随中、浏览暂停和已停止（带真实原因）。从不在末尾的位置开启时先进入浏览暂停；用户点击“回到末尾”才主动跳转。停止后不因路径重新出现自动恢复，重新打开/验证必须由用户发起。
- 复用现有窗口、字节选区与 EOF 定位；用户滚动、选区、搜索和 Go To 暂停，内部跟随定位不得被自身的滚动信号误判为用户操作。浏览暂停期间纯追加不得重新 `setText`，以免破坏原生选区、横向位置和阅读位置。
- 路径观察先区分同身份增长、截断、替换、缺失、不可读与身份不明；同长度且保留 mtime 的原子替换也必须停止。不能仅按 `exists + size/mtime` 漏掉删除/替换。既有 watcher 尚未登记路径；后续选择补齐观察或有界身份检测时，不得把已连接但未工作的 watcher 当作证据。
- 同身份增长的有界检查可以使用原 EOF 重叠和固定采样，但必须写明它不证明整个历史前缀未改变；Tail 不据此延长旧搜索结果的完整性承诺。当前 `DiskFileVersion.sampleHash` 含文件大小，不能直接将其整体相等作为追加判断。不能为每次追加在 UI 线程全扫文件。
- 安全类型策略仍归应用打开/持久化边界，Provider 不引用 KDBX 服务。候选源被替换成安全格式时，先拒绝再读取普通投影，零解锁；短生命周期读取需核对其实际文件身份，不能只预检路径后读取另一文件。保留现有不长期持有源句柄的原子替换兼容性。
- 现有每次刷新从头重建行号/字符数的行为不能直接沿用为连续追加实现。允许有界保留旧前缀、把新增区域行号/总字符数明确标为待更新；如做增量，复用既有唯一任务与 generation，只补最后稳定块和追加区，正确保留 CRLF/解码余量。不为本轮引入独立索引框架，不假报未完成的精确总数。
- 先复用既有 append/truncate、无长期 mmap、EOF gutter、行号/字符统计共用扫描回归，再补真实开关/暂停/失败/迟到提交。30 分钟采样是本轮有界与回收证据；CPU、RSS、句柄具体发布数值仍须由第 3 轮预算和实测明确，不提前宣称达标。

### 验收

- 逐批追加含 CRLF、UTF-8 多字节字符和跨块行的日志；每批末字节可见，无重复、缺口或半字符。
- 用户向上滚动后连续追加三批，viewport 与 selection 不动；点击“回到末尾”后一次定位到最新完整行并恢复跟随。
- append、truncate、原子 replace、delete/recreate、权限拒绝分别得到确定状态；旧 watcher 回调不能覆盖新文件身份。
- 30 分钟空闲与持续追加各记录 CPU、RSS、句柄、线程、UI heartbeat；具体阈值由第 3 轮性能预算固定，本轮先证明资源有界且关闭后回收。

### 2D 开发合同（2026-08-30，主代理设计，未验收）

- 首版覆盖普通只读 Provider 的 Text/Hex 两种呈现；可编辑文件、安全文档、账号页面和无源页面均不可用。`view.tail.toggle`（跟随文件末尾）与 `view.tail.resume`（回到末尾）有统一命令身份；命令执行入口重复检查当前源与能力，不能只依靠菜单灰显。默认不持久化开关，重新打开文件从关闭开始。
- `ReadOnlyTailController` 是文档级唯一跟随状态 owner，属于 editor runtime：负责四态、停止原因、用户意图、迟到 EOF 定位资格和固定状态条；不另建 watcher、线程、索引或搜索状态。Provider 继续拥有实际读取、同句柄准入、版本接纳和投影。允许以明确的小型事实/回调接入，禁止将 Tail 状态复制到 MainWindow/EditorTab。
- 状态条使用完整产品语言和可访问名称：关闭／正在跟随文件末尾／已暂停跟随，你可以继续查看上方内容／已停止跟随及具体原因；暂停时提供固定“回到末尾”按钮。用户从上方开启只进入暂停，不抢位置。只有显式回到末尾才清除阅读选区并到达最新 EOF。截断、替换、内容重写、删除、不可读、安全类型拒绝都会停止；路径恢复或普通自动刷新不能恢复跟随。“回到末尾”不能绕过停止；用户重新打开，或关闭后再次明确开启并通过新源验证，才建立新跟随基线。
- 变化分类必须保留真实 `DiskFileState` 及前后 identity/size/mtime。同身份增长还核对上一已接纳 EOF 前最多 64 KiB 重叠；重叠不一致视为内容重写并停止。该有界证据不证明全部历史未变，不保留旧搜索完整性。读到/接纳的版本再变化则拒绝本次提交，等待既有观察机制；普通离线安全准入保持不变。空文件开启也需真实准入，不伪造成功。
- 将刷新中的“接纳源版本”和“替换可见投影”分开：跟随中合并到最新 EOF；暂停且符合追加事实时只接纳新版本和更新长度/滚动范围，不 `setText`、不改变当前原生/字节选区、首可见行和横向位置。暂停之后的迟到 paint 不得再执行跟随定位。纯复制不暂停；向上滚动、拖滚动条离开末尾、任何新的选择、键盘浏览、搜索定位和 Go To 暂停。关闭开关只撤销 Tail 活动，原文档观察、搜索失效、只读保护继续。
- 开启后每次增长不再重启全文件统计任务。首版保守将旧字符总数/全局行号标为未更新，不把有界 EOF 证据当成完整前缀证明；已有后台结果通过原 generation 丢弃，避免重复扫描。必要的状态条说明“文件持续变化，行号和字符统计未更新”。关闭跟随后可按既有机制明确重建一次，Tail 活动期间不能由每批追加自动反复触发。现有投影/复制/样本上限不提高。
