# 第 6 轮：代码与脚本可视化验收契约

> 状态：设计完成；首批语言与 parser 供应链等待产品批准
> 更新日期：2026-08-30
> 前置条件：第 5 轮全部退出条件通过；与第 7 轮纯文本助手互不构成前置依赖

## 1. 面向非技术用户的产品结果

用户选择一段代码或脚本后，产品先给一句“它要完成什么”，再以可点击步骤解释：

1. **输入从哪里来**：参数、用户输入、文件、环境变量或已有数据。
2. **按什么顺序处理**：计算、转换、调用和组合。
3. **在哪里作判断**：条件成立/不成立分别去哪里。
4. **在哪里重复**：循环处理什么、何时停止。
5. **数据怎样流动**：某个值从创建、读取、修改到输出经过哪些步骤。
6. **会产生什么结果或影响**：返回值、文件写入、进程/网络调用、界面输出。
7. **哪些事无法仅凭代码确认**：运行时输入、外部文件内容、动态调用、反射或失败结果。

每个结论都能点击回到精确源码；图只表达 parser 能证明或保守推断的关系。AI 不参与事实边和副作用判定。

## 2. 首批范围与产品决定门

推荐首批语言为 Python、PowerShell、JavaScript：覆盖普通脚本、Windows 自动化与常见前端/Node 代码，且能共同暴露动态调用、管道和异步等难点。实现前需产品批准：

- 首批语言是否先批准其中一种，或采用 Python + PowerShell / 三语言组合；未获批语言不计入已承诺范围；
- 是否把固定版本 Tree-sitter core 与对应 grammar 源码纳入仓库锁、SBOM 和 GPL 兼容审查；
- grammar 更新责任、畸形语料和停止支持策略。

未批准时可完成语言无关 `CodeModel`、native graph 和 fake parser negative contract，但不得把测试 parser 作为用户功能交付。首批组合批准后，先让其中一个语言完成 6A–6D 的端到端旅程，再扩展其余获批语言；一个语言的中间验收不等于全部获批范围已经完成，也不阻塞第 7 轮纯文本任务。

## 3. 静态事实模型

固定流水线：

```text
ApprovedDocumentSlice
  → language resolver
  → pinned parser + bounded syntax tree
  → CodeModel
  → product-language steps + native graph
  → source navigation
```

`CodeModel` 只包含：symbol、scope、definition/use、call、branch、loop、return、read/write、external effect、typed edge、source range、confidence 和 unsupported reason。所有节点/边绑定 documentId、revision 与原 source range。

置信级固定为：

- **代码明确写明**：parser 可直接证明的定义、赋值、调用语法、分支、循环和返回。
- **可能发生**：动态语言别名、间接调用、可选模块、异常分支或外部状态造成的保守关系。
- **仅运行时可知**：文件/网络内容、动态 import/eval、反射、命令输出和用户输入结果。

不得使用“确定安全”“一定成功”“没有副作用”等超出静态证据的语言。

## 4. 切片 6A：语言识别、解析预算与敌对输入

### 设计

语言来自当前文档显式语言/扩展名/内容探测的可解释结果；不因一段文本看似代码而静默启用。parser 只接收获批 slice 的内存字节，不打开 import、include、module、profile 或工程文件；不执行 preprocessor、Shell、宏、包管理器或网络。

### 验收

- 每种语言覆盖完整/未完成/语法错、BOM、Unicode identifier、超长字符串、深嵌套、百万 token 倾向和随机字节。
- 默认节点 ≤500、边 ≤1000、嵌套/字符串/单节点文本/输入字节有硬上限；超过时安全截断并解释保留了哪条入口/关键路径。
- 解析可取消、超时和内存预算可测；旧 generation 结果不得覆盖新选择。
- 恶意 `import`、PowerShell profile/dot-source、JS getter/eval 字样只作为文本解析，系统证明零进程、零网络、零未授权文件读取。

## 5. 切片 6B：步骤说明与数据流

### 设计

解释器是确定性 `CodeModel → 产品句式` 转换，不把源码送模型。每个函数/脚本入口先生成一句目的摘要，摘要必须由可见的调用、返回和副作用拼成，并在无法判断业务目的时直说“代码名称和结构不足以确认用途”。

步骤按可执行结构排序，不按 AST 节点倾倒。变量数据流说明使用“创建 / 读取 / 更新 / 传给 / 返回 / 写入外部”，避免 SSA、AST、CFG、token、binding 等术语。

### 验收

- golden 对每条说明断言 source range、confidence、顺序和禁用工程词；同一结构只因命名变化时不发明新业务事实。
- 分支合流、早返回、异常、循环、闭包、async/await、PowerShell pipeline、Python comprehension、JS callback 有明确保守边界。
- 未使用值、可能为空、未处理失败只能表述为“代码中未看到……”；不得上推为运行时 bug。
- 点击说明定位并选中正确源码；源码变化后说明整体 stale，不以旧 offset 猜测。

## 6. 切片 6C：有界原生图与交互

### 设计

使用 Qt 原生图模型/绘制，不渲染工具提供的 HTML/SVG。默认展示入口、关键处理、判断/循环、输出/副作用；大图先按函数/作用域折叠。节点点击回源码，键盘可遍历，读屏读取“步骤、关系、置信级、源码位置”。

颜色不是唯一编码：节点同时有形状/图标/文字；边同时有方向、关系标签和可读列表视图。用户可在“步骤列表 / 数据流 / 调用关系”三种视图间切换，不同时堆满所有边。

### 验收

- 1、20、100、500 节点与 0、1000 边；窄宽窗口、100/125/200% DPI、深浅/高对比度、中文/长 identifier、键盘/读屏。
- 图首屏、布局、缩放/平移和点击有性能预算；布局在 worker 可取消，发布到 UI 的单批 <16 ms、任何事件 <50 ms。
- 图中零可点击外链、script、data URL、文件 URI、任意命令；复制只复制当前可见产品文本，不附源码以外的隐藏 payload。
- 同一 `CodeModel` 的列表与图 source range/edge count 完全一致；渲染器不能自行推断关系。

## 7. 切片 6D：首批语言产品旅程

每种获批语言至少有 30 个审核 golden：参数与返回、文件读取/写入、网络/进程调用语法、条件、循环、函数调用、错误处理、动态/无法确认边界和畸形输入。另以三段非技术用户可理解的真实脚本做整窗视觉旅程：

- 备份若干文件并报告失败；
- 读取表格/JSON、筛选并生成结果；
- 调用外部服务或程序，但明确只解释、不执行。

验收从选择 → 明确范围 → 解析 → 一句话用途 → 步骤 → 数据流图 → 点击回源码 → 修改源码后 stale。Plain 与已解锁 Secure 结果一致；Accounts denied；B2/B3 只在有界选区内允许，不后台读取全文。

## 8. 打回与退出

以下任一项立即打回：执行/导入脚本；读取未授权工程文件；AI 发明事实边；图与列表关系不一致；结论无源码范围/置信级；畸形输入无界；HTML/SVG 可执行内容；用 parser 存在代替获批语言 golden 和真实 GUI。

获批语言、固定供应链、6A–6D、KDBX ON/OFF、架构/供应链、性能和视觉全部通过后，第 6 轮才能关闭。
