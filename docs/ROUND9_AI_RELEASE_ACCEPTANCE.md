# 第 9 轮：AI 组合产品验收契约（不含安装发布）

> 更新日期：2026-08-30

文件名保留旧的 `AI_RELEASE` 以维持已有引用；本契约不执行 Windows 安装、打包分发、签名、升级/回滚安装、卸载、渠道或公开发布。

## 1. 组合验收定义

第 9 轮不再增加功能。它只验证核心记事本、代码可视化和获批 AI 组合后的真实用户旅程、数据边界与性能。任何新功能请求回到独立路线，不在组合验收中扩张范围。通过代表本次产品成熟度目标完成，不代表具备 Windows 公开分发资格。

组合候选必须同时满足：

- 一个可复核的 source identity、明确版本、产品功能总账和组合验收记录；
- 核心编辑/打开/保存/恢复/搜索完全不依赖 parser、模型或网络；
- 未配置模型时产品仍是成熟记事本，文档助手明确说明配置步骤，不出现错误循环或空壳按钮；
- 获批能力的 UI、实现、权限合同、实际 EXE/依赖和用户文档一致；未获批远程/语言/模型不注册、不暗藏入口；
- 零 P0/P1；P2 只允许有可理解降级、规避、负责人和目标版本。

## 2. 组合架构清理

### 必须删除或隔离

- Echo/StaticGraph/fake Provider、测试模型、故障注入、固定 token 流和测试 endpoint 不得进入生产注册表、产品 CMake target 或资源。
- 重复的 AI/Tool/Parser 状态、直接 EditorTab/MainWindow 读取、旧实验 adapter、legacy prompt/chat persistence 和未使用开关必须移除或保留在 tests/archive 的不可达范围。
- 产品 Release 构建不接受任意 Provider URL、任意 parser DLL、动态插件目录、自动模型下载或脚本执行入口。这里的 Release 是优化构建配置，不是安装发布活动。

### 必须保持

- 所有用户动作仍经 CommandId/FeatureId、Capabilities、ApprovedDocumentSlice、InferenceService/DocumentTool registry 和 typed Artifact/Proposal。
- 关闭、锁定、revision stale、取消与退出只有一个权威生命周期；结果、prompt 和模型输出不进入 session/Draft/crash log。
- 首帧前 Tool/Parser/Inference/模型重型实例为零；禁用/未配置能力只贡献轻量 descriptor。

## 3. 最终用户旅程

在记录身份的正式产品 EXE 与隔离测试数据上完成以下可见旅程，不使用用户真实笔记或账号：

1. 离线首次启动 → 新建 → 编辑 → 崩溃恢复 → 保存 → 重开；无需安装器或干净 VM 部署流程。
2. Plain Text/Binary、Secure Note、Accounts、B2/B3、编码/搜索/Tail、外部冲突和恢复问题的核心矩阵。
3. 选择普通文本 → 文本概览 → 整理空白 Diff → Apply → Undo。
4. 选择获批语言脚本 → 一句话用途 → 步骤 → 数据流图 → 点击回源码 → 源码变化后 stale；证明零执行/网络/额外文件读取。
5. 本地模型五任务：健康/模型身份 → 流式预览 → Cancel → 重新运行。解释/总结只读且不改正文；改写/续写/生成再完成 Diff → Apply → Undo。服务缺失/模型不匹配时核心编辑器继续可用。
6. 第 8 轮若拒绝远程：以获准、限定测试进程的动态证据证明本地失败时零远程外连，获批 loopback 单独记录；若另行批准远程：逐次授权、费用/保留、密钥、真实 E2E 与失败矩阵。证据缺失不能写成通过。
7. 直接加载受支持历史数据 schema、未知版本、损坏 session/恢复稿与安全文档：受支持数据可验证重开；未知/损坏格式 fail closed 且可恢复原件，不静默清空或覆盖。不执行 N-1/N-2 安装升级/回滚矩阵。

### 从历史分发轮迁入的运行质量门

- 暗色非选中标签必须可读；Tail 当前行通过不代表整个壳层对比度通过。复验深浅/高对比主题与不同 DPI。
- 检查真实 Windows UIA 暴露的动态 Name/Value、状态和键盘可达性；Qt `accessibleDescription` 或 QObject 属性非空不能代替读屏证据。
- 账号页长标题在此前恢复焦点截图中存在左侧裁切/横向滚动现象；需确认完整名称可读且关键操作不受遮挡，复验窄窗口、长中文/英文标题。该观察未构成修复或整页视觉通过。
- 会话、恢复稿、设置、Secure/Accounts 的版本识别与失败保全仍是运行时数据安全合同。发生 schema 变更时，先证明旧数据保留、单一权威 generation 和安全重开；不能以取消安装迁移为由跳过。

每条旅程绑定 case ID、输入 hash、屏幕/DPI/主题、操作、结果 hash、截图/录像 hash 和测试者；内部对象断言不能替代可见和磁盘结果。

## 4. 最终性能与隐私矩阵

- 30 轮启动、首屏、首输入、B2/B3、搜索、parser、图、local AI 首 token/总时长/取消；P50/P95、RSS/private bytes、句柄、线程、UI heartbeat。
- 比较 AI-disabled、AI-configured-idle、parser-used、model-running 四种状态；未使用功能不得让启动/空闲/核心编辑超出既有预算。
- 检查日志、AI 临时状态、crash dump 配置、temp 和剪贴板副作用：不得因 AI/工具自动落盘或泄露 prompt、正文、输出、密钥、恢复材料或路径。用户明确采用结果后，正常保存/加密恢复按原有授权合同执行，不误判为 AI 自动持久化。
- 模型/grammar/runtime/license/lock/SBOM/hash 与实际运行依赖逐项一致；许可证覆盖获批本地使用/测试，不在本轮要求模型分发权；没有运行时下载补齐缺失依赖。

## 5. 运行质量门与证据链

组合验收记录 source archive/hash、Git commit 与实际 dirty 状态、受验源文件、EXE hash、工具链、依赖锁、模型/grammar 身份，以及各测试的命令、时间、结果和 reviewer。共享脏工作树不能冒称 clean；未提交源变更也必须可以从冻结快照还原。

沿用既有架构/供应链、KDBX ON/OFF、适用 ASAN/内存安全、性能、恢复故障和人工视觉质量检查；按各轮契约绑定真实证据，不将静态检查、仅构建或 fake 测试写成动态通过。

`tools/run_release_gate.ps1` 保持原有严格含义，不修改脚本伪造发布 PASS。本次不要求其 `-Mode Full`、RG-08 包、RG-09 签名、RG-10 分发 provenance；相关底层质量检查单独执行并记入本契约。

每项已通过证据必须绑定匹配的 source/EXE/依赖身份、可重算 artifact hash 和非 pending 审核结果。改码或重建后保留历史证据但不得冒用；先判断影响范围，再为新候选重跑受影响的功能、性能和视觉门。

## 6. 缺陷与降级语言

- P0：数据破坏、秘密泄露、任意代码执行、认证/权限绕过、无法启动/保存/恢复。零容忍。
- P1：核心旅程不可达、错误文件/范围修改、silent remote fallback、模型/图事实误导且无提示、严重性能/资源失控。零容忍。
- P2：有安全替代路径的局部不可用或质量缺陷。必须在 UI/已知问题文档用用户语言说明影响、规避与修复目标，不泄漏内部术语。
- P3：不影响任务完成的轻微视觉/文案问题；登记并有负责人。

“AI 可能出错”不能豁免范围、权限、事实来源、Diff 或 Undo 缺陷。模型质量样本未达 rubric 时应打回相应任务，禁用只能作为安全状态，不能冒充所承诺能力已经验收。

## 7. 产品验收与停止条件

根代理负责设计与独立验收、失败打回子代理修复；产品价值与扩大权限的决定保留给用户。关闭本轮前确认：

- 本次获批功能范围、运行环境和数据兼容边界；
- parser 语言/供应链；本地模型/runtime/许可证/Secure 策略；远程选择；
- 最终组合验收记录与 P2/P3 清单；
- 用户文档准确说明离线能力、AI 数据位置、模型要求、限制与恢复方式。

若发现需要修改，退回相应轮次，生成新 identity 并重跑受影响证据。完成定义是“获批真实功能在同一候选上通过完整旅程，数据/性能/隐私证据可复核”，不是“代码都存在”或“文档写完”。不生成 release tag、签名包或公开下载；将来分发须另行授权与验收。
